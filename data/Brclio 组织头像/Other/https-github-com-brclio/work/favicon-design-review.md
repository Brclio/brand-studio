# Brclio Favicon 独立设计评审

评审对象：`brclio-clio-avatar-concept-02-flat.png`，并参考当前微标识草案 `brclio-favicon-source.svg`。  
结论：**采用独立的“B × Clio × 记录印记”微标识，不把完整头像机械缩小。** 当前草案方向正确：黄圆提供稳定外轮廓，蓝色 B 承担识别，奶油色侧影保留 Clio，红色卷轴点成为 16px 下仍可记住的锚点。

## 建议的几何结构

以 `64 × 64` viewBox 为母版，全部使用封闭填充路径，不使用描边、渐变、阴影或纹理。

- **外形**：圆心 `(32, 32)`、半径 `30` 的金黄圆；四周保留 `2u` 透明安全边，防止浏览器裁边。
- **蓝色 B**：控制在约 `x=15.5–56.5 / y=7.5–56.5`；左竖干有效厚度至少 `8u`，两段圆肚不能出现小于 `4u` 的颈部。外轮廓比内部叙事优先。
- **Clio 负形**：仅保留额头—鼻尖—唇—下巴—肩颈的一整块奶油色剪影，不保留眼睛、睫毛、发丝或白色外描边。鼻尖水平凸出建议不少于 `4.5u`，颈肩处最窄不要低于 `4u`，避免 16px 时糊成孔洞。
- **月桂**：32px 以上最多两片实心叶；单片约 `6–8u × 12–14u`，叶间净距至少 `3u`。若提供专门的 16px 栅格版本，建议合并成一枚 `2 × 5px` 的黄斜叶，而不是硬保留两片。
- **卷轴／印记 C**：右下放同心偏移圆：奶油色外圆 `r≈7.8u`、红圆 `r≈5.8u`、向右偏移约 `2.5u` 的黄圆 `r≈3.6u`。32px 时读作 C，16px 时自然退化成清晰红点，仍保留 10% 点缀色角色。

## 16px 与 32px 风险

- 当前两片月桂在 16px 会与蓝底抗锯齿混色，视觉上成为数个偏灰绿像素；这是目前最明显的小尺寸风险。首选做一份手工提示的 16px 图层：减为一片叶；次选是增厚叶片并拉开间距。
- 奶油色侧影在 16px 不应追求“看清五官”，目标是形成一块稳定、方向明确的头像负形。不要补眼睛或线条，它们只会制造脏点。
- 红色 C 在 16px 只有约 `3–4px` 总直径，奶油色分隔圈可能只剩半像素抗锯齿；允许它退化为红黄印记，不必强求读出字母 C。
- 任何小于 `2u` 的缝隙、尖角或描边都应删除。导出 16px 时建议使用高质量 Lanczos 缩放后人工目检，而不是只看 512px 预览。

## 深浅背景建议

- 默认保持黄圆外部透明。黄圆在 GitHub／浏览器的浅色标签页上提供温暖底色，在 `#0D1117` 或 `#151821` 暗底上也有足够轮廓对比；无需额外白边或阴影。
- 浅色背景推荐 `#FEFCF6`；暗色背景推荐 `#0D1117`。蓝、黄、红固定为 `#2B7FD8 / #F4D758 / #E84A5F`，奶油色固定为 `#FEFCF6`。
- 若网页自身使用大面积黄色背景，不要给 favicon 加深色描边；应改用带奶油色方形底的独立 app-icon 版本。浏览器 favicon 仍保留透明黄圆版。

## 推荐交付结构

- `favicon.svg`：上述 64u 母版，适合现代浏览器与 32px 以上显示。
- `favicon.ico`：至少包含 16、32、48px；其中 16px 层可使用“一片月桂”的手工简化版。
- `favicon-16x16.png`、`favicon-32x32.png`：便于兼容与直接检查。
- `apple-touch-icon.png`：180px，不透明奶油色底，图形安全区建议约 14%。
- `favicon-192x192.png`、`favicon-512x512.png`：PWA 使用；可保留两片月桂，但仍不恢复完整头像中的细线和纹理。

小尺寸验收标准：16px 一眼先读出“黄圆＋蓝 B＋红点”，32px 开始读出 Clio 侧影和卷轴 C；深浅背景均不糊边、不靠阴影成立。
